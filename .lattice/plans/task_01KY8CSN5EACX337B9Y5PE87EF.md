# FRAC-21: Refine mobile homepage hero composition

## Scope and layout ownership

- `src/components/layout/Navbar.tsx`: change only the unscrolled Home header below `lg`. Enlarge the bespoke Jacquard/Fraunces “Fractal Collective” masthead, add the exact visible descriptor `A NEIGHBORHOOD CAMPUS IN NYC`, retain the 44px+ hamburger and overlay behavior, and add stable data hooks for composition assertions. Do not change the desktop mega-nav, inner-page headers, or scrolled Home bar.
- `src/index.css`: keep the existing two-owner mobile Hero contract. `.hero-shell` owns viewport minimum height and enough top clearance for the larger fixed Home header; `.hero-stage` owns the complete octant layer and receives one compact-only upward adjustment so the canvas, projected labels, safe zone, and `FractalCityScene` hit region move together; `.hero-footer` remains an intrinsic, in-flow row. Art-direct `.hero-background-image` for portrait widths below `lg` with a less awkward skyline crop, while leaving the existing `lg` desktop rule byte-for-byte/effectively unchanged. Use the existing `md` refinement and `lg` structural boundaries, safe-area insets, and growth rather than fixed-height clipping.
- `src/components/sections/Hero.tsx`: enlarge the mobile intro blurb and “Explore our Story” label/icon/touch target using the existing Body/Chrome typography and foreground tokens; preserve its text, anchor semantics, `#story` behavior, pointer-event separation, and desktop-only search/caption. Add/retain data hooks needed to measure the footer/background composition.
- `src/components/three/FractalCityScene.tsx`: no camera-only or canvas-only offset. Preserve its full-bleed scene, shared `eventSourceRef`, `hero-hit-target`, `touch-action: pan-y`, aspect ratio, and OrbitControls wiring; the parent `.hero-stage` shift is what keeps the visible octant and interactive region aligned.
- `src/__tests__/navigation.test.tsx`: update the mobile Home-header contract for the larger masthead plus exact descriptor while retaining hamburger/overlay assertions.
- `tests/e2e/support/responsive-contract.mjs` and `tests/e2e/hero-responsive.spec.ts`: extend the shared Hero probe and focused tests to cover masthead/descriptor presence, containment and non-overlap, stage/hit-region alignment, footer/blurb/CTA containment, CTA minimum touch size, horizontal overflow, label safe zones, and the `lg` split (descriptor/mobile treatment hidden at 1024+, desktop footer still absent). Keep these runner-neutral so Playwright and Appium exercise the same contract.
- `tests/e2e/visual-evidence.spec.ts-snapshots/chromium-phone-320x568-home.png` and `chromium-landscape-640x360-home.png`: regenerate the two compact Home baselines after implementation. The 1024 and 1440 Home baselines are regression evidence that desktop is unchanged and should not need acceptance updates.

## Acceptance criteria

1. At 320–1023px, the initial Home header visibly gives “Fractal Collective” more prominence and shows exactly `A NEIGHBORHOOD CAMPUS IN NYC`; both fit with the menu control inside page/safe-area gutters with no overlap or horizontal scroll. At 1024px and above, the existing desktop navbar and Hero composition are unchanged.
2. On portrait phones, the entire octant composition is higher: rendered geometry, projected labels, safe zone, hit target, and drag/tap coordinate space remain aligned. Native vertical scrolling still passes through and horizontal drag/taps still operate the real scene.
3. The portrait skyline crop is deliberately recomposed below `lg` without changing the image pipeline, opacity, loading priority, or desktop crop. It does not expose empty edges during viewport/browser-toolbar changes.
4. The intro blurb and Story CTA are materially larger/readable, the CTA is at least 44×44 CSS px, retains keyboard focus and reduced-motion behavior, and still scrolls to an unobscured `#story` section.
5. Stage and footer remain separate layout rows; neither overlaps the other. The header, all projected labels, footer, and CTA remain visible/unclipped in normal portrait phone viewports, while short landscape and 200% text layouts may grow vertically and scroll instead of clipping required content.
6. No raw colors, alternate desktop breakpoint, fixed viewport clipping, camera-only translation, or `DESIGN.md` divergence is introduced.

## Verification matrix

1. Static/unit gate: `pnpm typecheck`, `pnpm test`, `pnpm build`.
2. Focused responsive gate: run `tests/e2e/hero-responsive.spec.ts` first, then `pnpm test:e2e:fast` across 320×568, 360×640, 640×360 landscape, 1023×1366, the 1024 boundary, 1440 desktop, 200% phone text, and reduced motion.
3. Full automated matrix: `pnpm test:e2e:full` across Chromium/Firefox/WebKit and all configured 320/360/375/390/412 portrait phones, four phone landscapes, 768/820/1023 tablets, 1024 boundary/iPad, 1280/1440/1920 desktops, 200% text profiles, and reduced motion. Review the two changed compact Home snapshots and confirm the 1024/1440 baselines remain unchanged.
4. Real S24-class Android emulator: run `pnpm simulators:doctor`, then `pnpm test:e2e:android-emulator -- --profile android-emulator-s24-class`. Inspect the generated portrait-expanded-toolbar, collapsed-toolbar-attempt, expanded-toolbar-attempt, and landscape screenshots/manifest. Confirm the enlarged header and exact descriptor, improved portrait skyline crop, higher octant with aligned native hit region, readable blurb/CTA, no clipping/overflow through browser-toolbar transitions, menu and Story CTA navigation, native octant drag/tap, rotation without reload, and no runtime/console failures. Perform the manifest’s manual largest practical Android font/display-scale check and an interactive toolbar collapse/expand check if automation marks it inconclusive.
